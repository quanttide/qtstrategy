# ROADMAP

转变轴：内部战略档案 → 对外战略公开站。起点是 `data/profile` 里按战略主体分层组织的 Markdown（`quanttide` / `qtalliance` / `qttech` / `qtdata` / `qtclass` / `qtcloud`，各一份 `index.md`），终点是外部读者能自己读、自己判的公开站。

阶段按「先能读、再能看、最后能查」排：数据源不通，后面全是手写死页；案例与指标建立在档案已被正确呈现之上；检索与多主体只有在条目量足够时才成立。

## v0.1.0 档案能读、能呈现

**达成标志**：站上战略内容来自 `data/profile/<主体>/index.md`，改档案文件页面即变，不依赖手写死页。

**顺序依据**：数据源接入是其余各项的前置——先有读数，才谈呈现。

**代价**：不做，「公开战略」只是手写介绍页，档案更新不影响站。

- [ ] 战略档案数据源接入：读 `data/profile` 下六个主体目录的 `index.md`
- [ ] 公开披露战略信息：战略方向、竞争力来源、产品观等章节按档案原样呈现
- [ ] 战略管理规范展示：章程、标准、工作手册三类各至少一篇渲染完成

## v0.2.0 有案例、有指标

**达成标志**：至少一个战略行动案例成页；站上至少两项指标由档案算出且写出计算口径。

**顺序依据**：案例与指标都以 v0.1.0 的数据通路为前提；无通路时只能手写，写完即过时。

**代价**：不做，站只能陈列战略原文，外部读者看不出这些战略执行得怎么样。

- [ ] 战略案例展示：一个案例成页，含背景、决策、结果三段
- [ ] 战略数据分析：给出至少两项从档案算出的指标（如主体数、章节数、章节字数），并在页面标出口径
- [ ] 移动端适配：375px 宽下首页与主体页无横向滚动

## v1.0.0 能查、能切

**达成标志**：输入关键词能定位到具体档案章节并跳转；站上可按战略主体切换，五个业务主体各有独立入口，内容互不串。

**顺序依据**：检索依赖条目已成规模，多主体切换依赖单主体读法稳定。

**代价**：不做，站止于单主体橱窗，外部读者无法按需取用。

- [ ] 战略档案检索：关键词命中具体章节并跳转
- [ ] 多主体支持：`qttech` / `qtdata` / `qtclass` / `qtcloud` / `qtalliance` 各有入口，同一站呈现
- [ ] 多组织支持：同一主体下列表随档案目录变化（新增或合并组织）呈现，不改代码
